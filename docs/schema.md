Mirror of Hermes **v2026.9.24**: `hermes_cli/web_server_dashboard.py`
(`_THEME_OVERRIDE_KEYS`, `_THEME_COMPONENT_BUCKETS`, `_THEME_NAMED_ASSET_KEYS`,

A theme is a YAML file in `$HERMES_HOME/dashboard-themes/`. Unknown top-level keys are
ignored; unknown keys *inside* a known block are dropped without a word, which is why
`theme-check.py` exists.

## Top-level keys

| Key | Status |
|---|---|
| `name` | required -- a theme without it is dropped entirely |
| `label` | shown in the picker; falls back to the name |
| `description` | shown under the label in the picker |
| `palette` | the three layers below |
| `colorOverrides` | the 19 permitted colours below |
| `typography` | see below |
| `layout`, `layoutVariant` | see below |
| `componentStyles` | see below -- mostly dead configuration |
| `assets` | bg, crest, header, hero, logo, sidebar |
| `customCSS` | raw CSS, hard cap 32768 bytes |
| `seriesColors` | **accepted but never reaches the surface** -- use customCSS with --series-input-token/--series-output-token and !important |
| `swatchColors` | **accepted but never reaches the surface** -- only the picker preview; has no effect on the dashboard |
| `terminalBackground` | **accepted but never reaches the surface** -- the xterm panel is painted by the app, not by the theme |
| `terminalForeground` | **accepted but never reaches the surface** -- the xterm panel is painted by the app, not by the theme |

## `palette`

| Layer | Meaning | Notes |
|---|---|---|
| `background` | the canvas | what every other surface is measured against; nothing else should be guessed if this is missing |
| `midground` | the ink | the default text colour; themes that only set this one still look deliberate |
| `foreground` | an overlay | a tinted layer drawn over the whole page; `alpha: 0` switches it off |

Each layer takes either a bare `"#rrggbb"` or the `{hex: "#rrggbb", alpha: 0.0}` form.
`palette.warmGlow` and `palette.noiseOpacity` are still accepted for compatibility with
older themes; both are retro decorations, and `noiseOpacity: 0` switches the grain off.

## `colorOverrides`

Exactly these 19 keys are permitted. Anything else is silently discarded.

| Key |
|---|
| `accent` |
| `accentForeground` |
| `border` |
| `card` |
| `cardForeground` |
| `destructive` |
| `destructiveForeground` |
| `input` |
| `muted` |
| `mutedForeground` |
| `popover` |
| `popoverForeground` |
| `primary` |
| `primaryForeground` |
| `ring` |
| `secondary` |
| `secondaryForeground` |
| `success` |
| `warning` |

Values must be strings. A bare `#rrggbb` is the only form guaranteed to render
everywhere; `color-mix()` and `oklab()` values are accepted but only work in a modern
browser.

## `componentStyles`

The server accepts 9 buckets and passes them through as
`--component-<bucket>-<kebab-prop>`. The shipped build reads only these:

| Bucket | Properties the build reads |
|---|---|
| `card` | `background`, `border-image`, `box-shadow`, `clip-path` |
| `header` | `background`, `border-image`, `clip-path` |
| `sidebar` | `background`, `border-image`, `clip-path` |
| `tab` | `clip-path` |

**Dead configuration** (accepted, emitted as a variable, never read): `backdrop`, `badge`, `footer`, `page`, `progress`.
Setting a colour there fakes a change that does not happen.

## `typography`

| Field | Used | What it is |
|---|---|---|
| `fontSans` | yes | the UI font |
| `fontMono` | yes | code blocks and the terminal |
| `fontUrl` | yes | a stylesheet URL, e.g. a Google Fonts link |
| `baseSize` | yes | root font size |
| `lineHeight` | yes | root line height |
| `letterSpacing` | yes | root letter spacing |
| `fontDisplay` | no | stored, but the shipped build never uses it -- headings need customCSS |

## `layout`

| Field | Accepted | Notes |
|---|---|---|
| `radius` | a CSS length | `1rem`, `12px` |
| `density` | comfortable, compact, spacious | falls back to comfortable |

`layoutVariant` is one of `cockpit`, `standard`, `tiled`.

## `customCSS`

Raw CSS in an injected `<style>` tag, capped at 32768 bytes (32 KiB) and
deliberately not sanitised -- a theme file has the same trust level as `config.yaml`.
This is the only lever for everything without a token: speech bubbles, code chips,
scrollbars, `::selection`, rounded-none surfaces, semantic status colours.

Two things it must handle that the schema cannot:

1. **Chart series colours.** `seriesColors` never arrives. Set
   `--series-input-token` / `--series-output-token` on `:root` **with `!important`** --
   the client writes them inline on `<html>`, and inline style wins.
2. **Semantic colours.** `colorOverrides.success/warning/destructive` are stored but the
   app hardwires those colours in its stylesheet; a `[class*="text-success"]` rule is
   what actually repaints the status chips.

## Builtin theme names

A user theme cannot shadow one of these: `cyberpunk`, `default`, `default-large`, `ember`, `midnight`, `mono`, `nous-blue`, `rose`.
